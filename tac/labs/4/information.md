# Theory behind Lab 4: finite automata and regular grammars

This file explains the theory that Lab 4 uses: what finite automata and regular grammars are, why they describe the same languages, and how that applies to the tokens of the recipe language. `doc.md` describes the implementation; this file explains why it works.

## 0. Quick brief: what to know for the presentation

**The task in one line.** Describe what a valid identifier and a valid constant look like using automata, then write a program that turns an automaton into a grammar.

**What a finite automaton (FA) is.** Think of a board game. You have a few squares (the states) and a starting square. Each character of the word tells you which arrow to follow to the next square. When the word ends, check where you are: on a "final" square, the word is valid. If there is no arrow for a character, you are stuck and the word is invalid.

**The identifier automaton (2 states).**
- Start in **S**. Only a letter takes you to **I**.
- In **I**, a letter, a digit or `_` keeps you in I.
- I is final, so `x_1` is valid. `2supa` gets stuck right away, because a digit can't be first.

**The constant automaton (5 states).** Start in **S**, and the first character decides the path:
- `0` goes to **Z**. Nothing can come after it, so `007` is invalid.
- `1`–`9` goes to **N**. Any number of digits may follow, so `200` is valid.
- `"` goes to **A**, which means "inside a string". Letters keep you in A, and another `"` goes to **C**, "string closed". `"sare2"` gets stuck on the `2`. `"piure` runs out of characters while still in A, which isn't final.

**What a regular grammar (RG) is.** A set of rules that writes a word from left to right, one character at a time:
- `I -> 'a' I` means: write `a`, then keep going with rule I.
- `I -> 'a'` means: write `a`, then stop.

**The conversion (FA → RG).** It's three simple rules:
1. Each state becomes a rule name. S stays S, I stays I.
2. Each arrow `p --a--> q` becomes the rule `p -> a q`.
3. If the arrow lands on a final state, also add `p -> a`, so the word may stop there.

There are two small extra details:
- If the start state is final (the empty word is valid), add `S -> ε`.
- States with no way out, like Z and C, produce no rules of their own, so the program removes them.

**Why it's correct.** Following one arrow in the automaton is the same as using one rule in the grammar. A path to a final state is the same thing as a derivation of the word, so both accept the same words.

**How to demo it.**
```
python3 fa.py fa/identifier.fa x_1 2supa
python3 fa.py fa/constant.fa 200 007 '"oua"' '"piure'
python3 test.py
```
For each word, `fa.py` shows the automaton's path and the grammar's derivation side by side. `test.py` checks 2801 words and shows that the automaton, the grammar and the Lab 3 regex all agree.

**Likely questions, with short answers.**

| Question | Answer |
|----------|--------|
| Why FA → RG and not RG → FA? | The task asks for one of them. The automata are what I designed, so the grammar is produced from them. |
| Are your automata deterministic? | Yes. Every state has at most one arrow for each character. |
| Is `done` accepted as an identifier? | The automaton accepts it. The lexer then checks it against the list of reserved words, as in Lab 3. |
| Why do Z and C disappear from the grammar? | They are dead ends with no rules of their own. The words ending there are still generated by the `p -> a` rules. |
| Why is an automaton enough for tokens, but not for whole programs? | Tokens have no nesting. Programs have `for … done` that must be balanced, which needs a stack (a parser). |
| How is this related to the Lab 3 regexes? | Regexes, automata and regular grammars are three ways to write the same thing. The test proves they agree. |

## 1. Alphabets, words and languages

- An **alphabet** Σ is a finite, non-empty set of symbols. For identifiers, Σ = {a, …, z, A, …, Z, 0, …, 9, _}.
- A **word** over Σ is a finite sequence of symbols, for example `x_1`. Its length is |w|, so |`x_1`| = 3.
- **ε** is the empty word, with |ε| = 0.
- **Σ\*** is the set of all words over Σ, including ε. **Σ⁺** is Σ\* without ε.
- **Concatenation** joins two words: if u = `ab` and v = `c`, then uv = `abc`. For every word w, εw = wε = w.
- A **language** is any set of words, L ⊆ Σ\*.

Each class of lexical tokens is a language:

- L_id = { words made of a letter followed by letters, digits or `_` } = { `i`, `omleta`, `x_1`, … }
- L_const = { `0`, `1`, …, `200`, … } ∪ { `""`, `"oua"`, … }

A lexer has to decide, for a piece of the source text, which of these languages it belongs to. This is the **membership problem**: given w, is w ∈ L? Finite automata solve it in a single left-to-right pass, using one step per symbol and a fixed amount of memory.

## 2. Where regular languages fit: the Chomsky hierarchy

Grammars are classified by the form of their productions:

| Type | Name | Production form | Recognised by |
|------|------|-----------------|---------------|
| 0 | unrestricted | α → β | Turing machine |
| 1 | context-sensitive | αAβ → αγβ | linear bounded automaton |
| 2 | context-free | A → γ | pushdown automaton |
| 3 | **regular** | A → aB, A → a (S → ε) | **finite automaton** |

Each type contains the ones below it: every regular language is context-free, but not every context-free language is regular.

A compiler uses this split between its phases:

- **Tokens** (identifiers, constants) have no nesting, so a finite memory is enough to recognise them. They are type 3 and handled by the lexer (Lab 3) with finite automata (Lab 4).
- **The program structure** in `../2/bnf.txt` contains `List( [ … ] )` and `for … done`, which have to be balanced. That needs unbounded memory (a stack), so the full language is type 2 and is handled by the parser. Section 9 shows why it cannot be regular.

## 3. Finite automata

### 3.1 Definition

A **finite automaton** is a 5-tuple M = (Q, Σ, δ, q0, F):

| Symbol | Meaning |
|--------|---------|
| Q | finite set of states |
| Σ | input alphabet |
| δ | transition function |
| q0 ∈ Q | initial state |
| F ⊆ Q | set of final (accepting) states |

The form of δ decides the kind of automaton:

- **DFA** (deterministic): δ : Q × Σ → Q. From each state, each symbol leads to at most one state.
- **NFA** (nondeterministic): δ : Q × Σ → P(Q). From a state, a symbol may lead to several states, or to none. P(Q) is the set of all subsets of Q.
- **ε-NFA**: the automaton may also change state without reading a symbol. Lab 4 does not use this.

A state is the automaton's only memory. Since Q is finite, a finite automaton can remember only a bounded amount of information about what it has read. For example, state I of the identifier automaton remembers only that what was read so far is a valid identifier.

### 3.2 Configurations and acceptance

A **configuration** (q, w) is the current state q together with the input w that has not been read yet.

- A **move** is written (p, aw) ⊢ (q, w), where q ∈ δ(p, a). The automaton reads a and goes from p to q.
- ⊢\* means zero or more moves. Formally, it is the reflexive and transitive closure of ⊢.

The **language accepted** by M is:

L(M) = { w ∈ Σ\* | (q0, w) ⊢\* (q, ε) for some q ∈ F }

In words: a word is accepted if, after reading all of it, the automaton can be in a final state.

The same thing can be written with the **extended transition function** δ̂ : Q × Σ\* → P(Q), which gives the states reached after reading a whole word:

- δ̂(q, ε) = {q}
- δ̂(q, wa) = ⋃ over p ∈ δ̂(q, w) of δ(p, a)

Then w ∈ L(M) if and only if δ̂(q0, w) ∩ F ≠ ∅. This is exactly what `FA.run` / `FA.accepts` in `fa.py` compute: they keep the set of current states and update it once for each symbol.

### 3.3 Representations

An automaton can be written in two equivalent ways:

- a **transition table**: one row per state and one column per symbol. The initial state is marked →, final states ←, and `-` means there is no transition.
- a **transition graph**: states are nodes, final states have a double circle, and each transition is an arrow labelled with its symbol.

Example, the identifier automaton (letter = a..z A..Z, digit = 0..9):

| δ | letter | digit | `_` |
|---|--------|-------|-----|
| → S | I | - | - |
| ← I | I | I | I |

### 3.4 Partial and complete DFAs

A DFA is **complete** if δ(q, a) is defined for every state q and every symbol a. It is **partial** if some transitions are missing. In a partial DFA, reaching a missing transition rejects the word.

A partial DFA can always be made complete by adding a **sink state** E. E is not final, and every transition loops back to E. Every missing transition is then sent to E. The identifier automaton completed this way:

| δ | letter | digit | `_` |
|---|--------|-------|-----|
| → S | I | E | E |
| ← I | I | I | I |
| E | E | E | E |

Both forms accept the same language. The partial form is shorter, so Lab 4 uses it. A run that gets stuck, such as `2supa` in state S, is the same as falling into E. For a lexer, this is the moment a lexical error is detected.

### 3.5 NFA = DFA: the subset construction

NFAs are not more powerful than DFAs. For every NFA N there is a DFA D with L(D) = L(N). This is the theorem of Rabin and Scott, and the method is the **subset construction**:

- Each state of D is a set of states of N.
- The initial state of D is {q0}.
- From a set P on symbol a, D goes to ⋃ over p ∈ P of δ(p, a).
- A set is final if it contains at least one final state of N.

In the worst case D has 2^|Q| states, but usually only a few of these sets are reachable. `fa.py` does the same thing while reading the word: `run` keeps the current set of states and builds only the sets the word actually needs. This is why the same code works for both DFAs and NFAs.

### 3.6 Minimal DFAs

Two states p and q are **equivalent** if, for every word w, reading w from p ends in a final state exactly when reading it from q does. Merging all equivalent states gives the **minimal DFA**, which is unique up to the names of the states (Myhill–Nerode theorem).

In the constant automaton, Z (after `0`) and C (after the closing `"`) are equivalent. Both are final and both have no outgoing transitions, so from either of them only ε is accepted. A minimal DFA would merge them into one state. Lab 4 keeps them separate on purpose, because each one has a clear meaning ("the number zero" vs "a closed string"), and that makes the automaton easier to explain. The language is the same either way.

## 4. Regular grammars

### 4.1 Grammars and derivations

A **grammar** is a 4-tuple G = (N, Σ, P, S):

- N - non-terminals
- Σ - terminals, with N ∩ Σ = ∅
- P - productions
- S ∈ N - the start symbol

One **derivation step** uA v ⇒ u γ v rewrites a non-terminal A using a production A → γ. ⇒\* means zero or more steps. The language generated by G is:

L(G) = { w ∈ Σ\* | S ⇒\* w }

### 4.2 Right-linear (regular) grammars

G is **regular** (right-linear) if every production has one of these forms:

- A → aB, with a ∈ Σ and B ∈ N
- A → a
- S → ε, allowed only when S does not appear on the right-hand side of any production

With these forms, every derivation step adds exactly one terminal, and the only non-terminal is always at the right end of the sentential form:

S ⇒ a₁A₁ ⇒ a₁a₂A₂ ⇒ … ⇒ a₁a₂…aₙ

So a non-empty word w has a derivation of exactly |w| steps.

**Why the ε rule is restricted.** If S → ε were allowed while S also appears on a right-hand side, ε could be used in the middle of a derivation and steps would no longer add exactly one terminal each. The language would still be regular, but the one-to-one match with automaton moves in section 5 would break. The restriction means ε is used only to generate the empty word itself.

**Equivalent variants.** The following grammars also generate exactly the regular languages:

- *extended* right-linear grammars, with productions A → wB and A → w, where w ∈ Σ\*
- *left-linear* grammars, with productions A → Ba and A → a

Each can be converted to the strict form above.

**But not a mix.** If a grammar mixes left-linear and right-linear productions, it may stop being regular. For example, S → aA, A → Sb, S → ab generates { aⁿbⁿ | n ≥ 1 }, which is not regular (section 9).

## 5. Equivalence of finite automata and regular grammars

**Theorem.** A language is accepted by a finite automaton if and only if it is generated by a regular grammar.

The proof consists of two constructions, one for each direction. Lab 4 implements the first one.

### 5.1 FA → RG (implemented in `fa_to_rg`)

Given M = (Q, Σ, δ, q0, F), build G = (Q, Σ, P, q0), where each state becomes a non-terminal:

1. For every transition q ∈ δ(p, a), add p → a q.
2. If also q ∈ F, add p → a.
3. If q0 ∈ F, add q0 → ε. If q0 appears on a right-hand side, first add a new start symbol S' with a copy of all of q0's productions plus S' → ε.

**Proof idea.** By induction on |w|, for all p, q ∈ Q and w ∈ Σ⁺:

q ∈ δ̂(p, w)  ⟺  p ⇒\* w q

- Base case, w = a: q ∈ δ(p, a) holds exactly when the production p → a q exists.
- Step, w = va: q ∈ δ̂(p, va) holds exactly when there is an r ∈ δ̂(p, v) with q ∈ δ(r, a). By induction, that is p ⇒\* v r, and then r ⇒ a q is one more step.

Now take a non-empty word w = va. It is accepted by M exactly when some r ∈ δ̂(q0, v) has a transition on a into a final state. That is exactly when q0 ⇒\* v r ⇒ va, where the last step uses the production r → a from rule 2. The empty word is covered by rule 3. Therefore L(G) = L(M).

**Intuition.** A non-terminal of the grammar has the same meaning as the corresponding state: "this is what the rest of the word may look like from here".

### 5.2 RG → FA (the other direction)

Given G = (N, Σ, P, S), build M = (N ∪ {K}, Σ, δ, S, F), where K is a new final state:

1. For every A → aB, add B ∈ δ(A, a).
2. For every A → a, add K ∈ δ(A, a).
3. F = {K}, plus S if S → ε ∈ P.

The result is usually an NFA, because A → aB and A → a both read a from A. The subset construction (section 3.5) then turns it into a DFA.

**Round trip example.** Start from G_id: S → letter I | letter, I → letter I | digit I | _ I | letter | digit | _.

- RG → FA gives an NFA with S --letter--> {I, K} and I --letter, digit, _--> {I, K}.
- The subset construction gives two reachable sets: {S} and {I, K}. Only {I, K} is final, because it contains K.

Renaming {S} to S and {I, K} to I gives back exactly the original identifier automaton.

## 6. Regular expressions and Kleene's theorem

Lab 3 described the tokens with regular expressions. A regular expression is built from:

- ∅, ε, and single symbols a
- **union** r | s
- **concatenation** rs
- **Kleene star** r\*, meaning zero or more repetitions of r

**Kleene's theorem:** a language is described by a regular expression if and only if it is accepted by a finite automaton. Together with section 5, this gives three equivalent ways to describe the same class of languages:

```
     regular expressions
        /          \
 finite automata --- regular grammars
```

The parts of a regular expression map directly onto automata:

| Regex part | Automaton shape | In Lab 4 |
|------------|-----------------|----------|
| `ab` (concatenation) | a chain of states | `"` then letters then `"` |
| `r*` (star) | a loop on a state | I loops on letter/digit/`_`; N loops on digit |
| `r \| s` (union) | branches from one state | the number branch and the string branch from S |

The Lab 3 regexes and the Lab 4 automata describe the same languages, and `test.py` checks this:

| Token | Regex (Lab 3) | Automaton (Lab 4) |
|-------|---------------|-------------------|
| identifier | `[A-Za-z][A-Za-z0-9_]*` | S → I, loop on I |
| number | `0\|[1-9][0-9]*` | S → Z, S → N, loop on N |
| string | `"[A-Za-z]*"` | S → A, loop on A, A → C |

Python's `re` module supports some features that go beyond regular languages, such as backreferences `\1`. The Lab 3 patterns use none of them, so they really are regular expressions in the theoretical sense.

## 7. Closure properties used in Lab 4

Regular languages are **closed** under union, concatenation, Kleene star, intersection and complement: applying any of these operations to regular languages gives another regular language.

**Union is how the constant automaton was built.** Take:

- a number automaton with states S₁, Z, N
- a string automaton with states S₂, A, C

Their state sets are disjoint, and neither start state has incoming transitions. Merge S₁ and S₂ into one start state S that keeps the outgoing transitions of both. The result accepts L_number ∪ L_string.

The result is still deterministic, because the two branches start with different symbols: digits for numbers, `"` for strings. If they shared a first symbol, the union would be an NFA and would need the subset construction.

**Complement** explains error detection. Complete the DFA with a sink state, then swap final and non-final states. The new automaton accepts exactly the malformed lexemes. This is the language that the "bad number" and "bad string" patterns in Lab 3 approximate.

## 8. How a lexer uses finite automata

A lexer runs the automata of all token classes in parallel. In theory, this is the union automaton of all the classes. It needs two rules that pure automata theory does not give:

- **Longest match (maximal munch):** keep reading as long as the automaton can still go on, and stop at the last final state reached. This is why `carbonara_non_italiana` is one identifier and not `carbonara` followed by `_non_italiana`.
- **Priority:** when the same lexeme belongs to several classes, choose by a fixed order. `done` is accepted by the identifier automaton, but it is a reserved word. Lab 3 first recognises the lexeme as identifier-shaped, then checks it against the list of reserved words.

Tools such as `flex` build one DFA for all the patterns and apply both rules directly. Python's `re` works differently: it tries the alternatives of `a|b|c` from left to right and takes the first one that matches (each alternative is greedy). That is why the order of the patterns in `../3/lexer.py` matters, and why error patterns such as `0[0-9]+` are placed before the correct ones.

When the automaton gets stuck, there are two cases:

- It reached a final state earlier: a token ends there, and scanning continues from that point.
- It never reached a final state: a lexical error is reported, such as `007`, `"sare2"` or `"piure`.

## 9. Limits: what finite automata cannot do

**Pumping lemma.** If L is regular, there is a number p ≥ 1 such that every w ∈ L with |w| ≥ p can be split into w = xyz with:

- |xy| ≤ p
- |y| ≥ 1
- xyⁱz ∈ L for every i ≥ 0

The reason is that a DFA with p states must repeat a state while reading the first p symbols. The part read between the two visits (y) can then be repeated any number of times, or removed, and the word is still accepted.

This can be used to show that a language is not regular. Look only at the loop keywords of the recipe language: properly nested loops give words of the form `forⁿ doneⁿ`. Take w = `for`ᵖ `done`ᵖ. Because |xy| ≤ p, the part y contains only `for`s. Pumping it gives more `for`s than `done`s, which is not a valid program. So the whole language is not regular, and the parser (type 2, section 2) needs a stack. The tokens themselves have no nesting, so finite automata are enough for them.

## 10. Notation summary

| Notation | Meaning |
|----------|---------|
| ε | empty word |
| Σ\*, Σ⁺ | all words / all non-empty words over Σ |
| δ(p, a) | states reached from p by reading a |
| δ̂(p, w) | states reached from p by reading the word w |
| (q, w) ⊢ (q', w') | one move of the automaton |
| ⊢\*, ⇒\* | zero or more moves / derivation steps |
| A → aB | production: A is rewritten as a followed by B |
| uAv ⇒ uγv | one derivation step |
| L(M), L(G) | language accepted by M / generated by G |
| P(Q) | set of all subsets of Q |
